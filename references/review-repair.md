# 审查、返工与批修

仅已有图模式读取。先区分只审查与修改授权；只审查时不创建备份、报告文件或预览文件，直接在对话中报告，除非用户另要求保存报告。

## 定位与判断

在指定范围内建立“目标图片 → 生成源码/函数 → 保存结果”对应关系。看实际图片并查相关源码，不只靠文件名判断质量。缺源码或数据时，可以进行视觉审查，但应标明数据真实性无法核验，不能根据图片猜值重绘。

按三类描述问题，不给模糊的审美分数：

| 类别 | 典型问题 | 处理 |
| --- | --- | --- |
| 数据与表达 | 口径不明、单位错、点缺失、误导尺度、图型错配 | 先核实；可由已有依据修正的呈现问题直接修正，涉及分析决定的交给用户 |
| 可读性 | 乱码、裁切、图例遮挡、重叠、最终尺寸字太小 | 在源码中修复，核对成图 |
| 专业性与美观 | 风格不一致、配色混乱、线宽失衡、留白失衡 | 在忠实性和范围内优化，不增加装饰或无依据标记 |

用户明确指出的调整方向优先执行；它若会改动建模结果，要说明冲突并请用户决定，不能借美化改分析。

只换配色时按 [palette-guide.md](palette-guide.md) 处理，保留其余呈现参数及数值编码；已有图发现其他问题可报告，不顺便扩大修改。每次换色默认只试当前目标，不改项目默认；只有明确确认后续统一采用才更新配置。

## 修改前保留证据

有修改授权后，在项目现有审查目录记录本批；若没有约定，使用 `<PROJECT_ROOT>/figure_review/<时间戳>/`，冲突时加序号，不覆盖旧批。

- 在 `before/` 按项目相对路径复制目标源码、目标图和将修改的共用模块；若将改项目配色配置，也备份该文件，保留未提交改动。不是 git 重置，也不是全项目备份。
- 简短 `review.md` 记录本批目标、来源/输出位置、修改方向、输入文件核对、运行及视觉检查、自动返工次数、未解决项和人工确认状态。不创建额外日志系统，不自动调用 AI 日志 skill。
- 输入文件可记录哈希，修改前后对照；还须核对绘图字段、映射和 artist 数据。只哈希一致不足以证明画图忠实。

## 修改与运行

优先修改原绘图函数，保留原调用关系及论文引用。明确错配可换图型，但不得删减数据或改变统计含义；说明依据。合理且已清晰的图只做必要的专业性调整，不为证明工作量而重做。

若入口会重拟合：先找已有 figure-only 功能；否则在不触动模型逻辑的前提下分离只读保存结果的出图入口。无法分离或缺少保存结果就停止该目标，不运行主建模流程。

共享模块修改前查调用方。局部覆盖即可解决时不改全局默认；确需影响非目标图时先提出扩大范围，不静默修改或全量重跑。批量任务复用本批样式和环境判断，但逐张检查结果。只影响某一目标的问题可隔离后继续其余已授权目标；共用环境故障不要对每张图重复试错。

保存前已经备份的目标可明确使用覆盖选项；保留仍被论文引用的原格式，并增加矢量版本。不要删除旧图、覆盖结果文件，或自动替换论文里的图片引用。

运行及自动返工上限依入口执行，不另设一套循环。反馈只需逐图给出“已运行/未运行、已看图/未看图、解决/未解决”和实质改动；只有用户明确确认后，才能更新人工确认状态。
