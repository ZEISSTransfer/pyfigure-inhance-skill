# 基础审美：角色、空间与检查

首次绘图必读；已有图涉及美化、布局或视觉层级时读取。**本文件为 2026-09-10 用户认可的新增工程建议，不来自课程截图，也不是期刊或比赛评分标准。** 字体、字重、轴线、标题、数据忠实性沿用入口和样式参考，不在这里另设版本。

## 出图前只确定四件事

在已有任务信息中确定：主数据是什么、哪些已有要素需要强调、最终使用宽度/暂定宽度、图例与色条放在哪里。用源码参数或几句说明即可，不额外创建设计报告，也不常规生成多套方案。

| 决策 | 默认起点 | 不适用时 |
| --- | --- | --- |
| 数据与强调 | 数据是主体；已有阈值、基准用一种可辨强调方式；辅助网格最弱 | 多个真实基准保留，靠线型和已有语义区分，不删减 |
| 非负频率/强度 | 未指定且未确认顺序色时，用 `palette_cmap("sequential", purpose="magnitude", project_root=ROOT)`，临时浅低深高的 Blues | 用户指定或项目已确认方案优先；不反转/截断 norm 来制造对比 |
| 无分类编码需求的柱/线 | 单一协调数据色；分类色只表达真实系列 | 不给每根柱随机分色；不能把合理多系列改成难辨同色 |
| 强调色 | 先沿用语义映射；没有时从当前分类色板明确选取与背景可辨的一色 | 不机械取第一色，不为强调而改变现有数值颜色编码 |
| 普通坐标图 | 先用原生子图和 tight_layout；图例能清楚放置时不增加新布局 | 需要图外图例时用 `outside_legend`；不要遮挡主图来凑版面 |
| 右侧色条 | 为刻度和水平名称预留侧边区域，再用 `add_right_colorbar` 跟随主图上下对齐 | 多图共享、横向或带延伸端帽色条用原生布局，不强行套辅助接口 |

零值、缺失值和未发生事件是不同概念。不能为了大片空白把零值转成缺失，也不能为了色彩饱满填零。若已有表达把零值留白，核对“白色零值—深色极小值”是否导致低值过度抢眼，优先在允许选色范围内改善；保留真实语义并说明必要约定。

## 角色化样式，而非全部加重

模板 `role_style` 给出可调整起点：轴标签比刻度大 2 pt，标数略小；文字全部 bold。数据线约 1.8 pt，已有基准线约 1.1 pt，浅色网格约 0.45 pt。**这些不是新增硬下限**，不得覆盖入口固定要求；按成图和最终论文缩放调整。不统一改写所有 artist，也不自动新增基准线或网格。

- 网格只帮助读取：趋势图按需要保留一个方向，矩阵边界保持轻；不要把坐标轴的黑色加粗规则套给网格。
- 已有基准框清晰即可，避免粗框、饱和背景、大标数同时抢眼。颜色编码本身承担主要信息时，不另添强调装饰。
- 对平坦单元格，使用 `annotation_color(cmap(norm(value)))` 选择黑/白字。传入实际背景 RGBA；若有独立透明度，先反映到 RGBA，再提供实际底色。不用 value < 0.5 代替背景判断。渐变、纹理或多层遮盖须看图，不自动加外晕。
- 稠密图不默认逐点/逐格标数。已有必要数值不能自行删掉；先调整布局或提出分面建议，必要时请用户决定表达取舍。

## 空间调整顺序

1. 先按论文拟用宽度检查主图区、轴标签和标数；没有尺寸信息可沿项目约定，标明暂定。不默认放大画布后又在论文里缩小，导致字体缩水。
2. 先为图例、横向标签和色条预留区域；同一色条从其主轴获取位置，不分别硬编码两套纵坐标。长标签允许有语义的换行，不改词语。
3. 默认 tight_layout；关联色条辅助采用外置 Axes，先对主轴做带 rect 的 tight_layout，再创建色条，导出用 preserve 并说明。主图移动后色条跟随，但辅助代码不会替你腾空间。
4. 空间仍不足，先调整图例列数、标签换行和边距；涉及数据比例含义时不得拉伸主图。只有确实需要才改画布尺寸，并核对最终缩放。不要通过字号不断缩小、删系列或裁掉数据解决。

不存在适用于所有图的主图占比、宽高比或留白百分比。分布中真实空白区域不是“浪费”，不能因此截断坐标或删零值行。

## 初检与一次定向返工

自动检查负责发现：主图区物理尺寸偏小、所选色条上下错位、图外图例靠边或压主图、过粗的主网格。阈值只是复核提示，不给“审美评分”；小分面或合理短色条可说明理由保留。

Agent 仍须看实际图，逐项判断：①主图是否被侧标挤瘦；②网格/框线是否抢过数据；③图例/色条是否协调对齐；④最终尺寸是否过密、留白是否明显失衡。每项只需指出实质问题，不机械产出长报告。

看图能明确指出的缺陷可使用入口规定的**同一次返工机会**：写清“哪个元素—什么问题—改哪个参数”，合并处理；不因为个人更喜欢另一种颜色循环试图。只换色任务不授权改布局，其他问题报告即可。人工验收与 Agent 检查分开。

## 维护验证边界

代码测试不证明模型审美。独立首次绘图测试应只给 CSV、字段/统计口径说明和 skill，不给旧出图源码、旧图或预期美化方案。用一张连续面图、一张标数矩阵和一张折线/条形即可覆盖主要部件；记录模型/推理设置和是否人工认可。维护者自写样张仅证明接口效果，不能冒称独立模型从零测试已通过。
